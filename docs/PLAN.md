# 三天交付计划

总预算约 20–24 小时，计划 23 小时；阶段 0 约 2 小时。后续阶段划分是估算，用户随后发送的阶段 prompt 优先；每次只完成当前阶段和必要修复，通过后一个有意义的本地 commit，汇报后停止。不凑提交数，不 push、打标签或发布。

| 天 / 阶段 | 预算 | 工作及验收入口 |
| --- | --- | --- |
| 第一天：0 可行性与范围 | 2h | 字节往返、argv/退出/信号、超时树清理、大输出、Ctrl-C；固定实测版本；骨架 check/build；SPEC/PLAN/STATUS |
| 第一天：1 纯缩减核心 | 4h | 确定 ddmin 请求/反馈状态机，位置身份、三态、空/单元素/重复/非单调、最终单删检查；独立于 OS；行为测试验证 |
| 第一天/二天：2 Native 驱动 | 6h | 正式 CLI、逐字节 LF 段、真实 oracle、隔离候选、超时/进程树与中断清理、输出原子保存；修复探针暴露的生产错误路径 |
| 第二天：3 预算与报告 | 4h | 统一调用计数、预留最终复验、输出路径复验、停止原因/目标行为/最小性独立状态，摘要+JSON；预算/异常集成验收 |
| 第三天：4 使用案例与库消费 | 5h | 可复现开发者调试流程，人工缺陷如实标注；独立 MoonBit 消费工程；端到端反例、README、错误处理/边界必要回归 |
| 第三天：5 独立复现与收尾 | 2h | 干净环境按 README 构建和真实工作流跑通；检查许可证/参考/范围/报告准确性；交付 commit 和已知限制 |

采用最小依赖路线：核心使用 MoonBit 标准序列/集合能力，参数和 JSON 使用随工具链的 core，文件和进程使用固定 async 版本，Linux 组管理使用已验证的 setsid/kill。阶段 0 不实现 ddmin 或正式缩减 CLI；探针只证明 API 和处理路径。

关键风险已有可运行路径：async 旧版信号返回歧义通过固定 0.22.4 解决；默认单 PID 取消不足，通过独立进程组、不可取消清理、真实三层进程树和外部 SIGINT 探针验证。下一阶段生产化仍须处理辅助信号发送失败的准确诊断、输出冲突/写失败与报告一致性，不能直接把探针当作完整驱动。

优先保证正确性、错误处理、进程清理、预算和最终复验。缓存是可删优化，首版不依赖；不将 AST、多文件、并行、GUI、多平台纳入预算。若后续关键验收无法完成，报告具体阻塞与最小下一步，不用 stub 或降低验收掩盖。

项目价值以实际调试流程和可复用库验证，不以代码行数、测试数或 MoonBit 暂缺该工具证明。公开索引已有同名相关项目，需如实记录相近工作；比赛批准、重复选题判断及当前赛事适用规则由主办方决定。
